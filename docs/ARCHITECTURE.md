# Архитектура ArchiVarious

ArchiVarious состоит из двух продуктов с общим ядром:

1. **Плагин Obsidian.** Он принимает заметки, через заданное время проводит короткий опрос и раскладывает заметку по хранилищу.
2. **Виджет-приложение.** Это кроссплатформенное окно быстрого ввода для Windows, macOS, Linux, Android и iOS. Оно позволяет записать мысль, не открывая Obsidian.

```
                ┌───────────────────────────── packages/core (TypeScript, без зависимостей) ─────────────────────────────┐
                │ лёгкое форматирование · планировщик опроса · алгоритм размещения · протокол «Входящих» (Markdown + YAML) │
                └───────────────▲───────────────────────────────────────────────────────────────▲──────────────────────────┘
                                │                                                               │
                ┌───────────────┴────────────── packages/ui (Svelte 5) ─────────────────────────┴───────┐
                │                         QuickCapture: одно поле ввода для всех поверхностей            │
                └───────────────▲───────────────────────────────────────────────────────────────▲───────┘
                                │                                                               │
   ┌────────────────────────────┴───────────┐                         ┌─────────────────────────┴───────────────────────┐
   │ apps/obsidian-plugin                   │   файл во «Входящих»    │ apps/widget (Tauri 2)                           │
   │ • модалка ввода, команда, кнопка       │◀───────────────────────│ • десктоп: окно поверх всех, глобальная клавиша │
   │ • опрос по расписанию                  │                         │   Ctrl/⌘+Shift+Space, иконка в трее             │
   │ • индекс хранилища → алгоритм          │◀───────────────────────│ • мобильные: приложение + нативные виджеты       │
   │ • перенос заметки и обучение           │  obsidian://archivarious│   рабочего стола (WidgetKit / Glance)           │
   └────────────────────────────────────────┘                         └─────────────────────────────────────────────────┘
```

## Жизненный цикл заметки

1. **Ввод.** Пользователь пишет текст в любой поверхности: в плагине, в десктопном окне или в мобильном виджете.
2. **Лёгкое форматирование** (`core/format.ts`). Нормализуются пробелы, первая буква становится заглавной, из текста извлекаются теги, ссылки и короткий заголовок. Слова пользователя не меняются, а исходный текст хранится в поле `raw`, поэтому форматирование можно пересчитать.
3. **Входящие.** Заметка ложится файлом в `ArchiVarious/Inbox/` с полем `survey_at` во frontmatter (`core/inbox.ts`).
4. **Отложенный опрос** (`core/schedule.ts`). По умолчанию опрос приходит через 6 часов: контекст к этому времени успевает «осесть», но пользователь ещё помнит, зачем делал запись. Тихие часы (23:00–8:00) пропускаются.
5. **Алгоритм** (`core/placement.ts`). Он предлагает до 3 папок по совпадению тегов и терминов с профилями папок. Опрос (`core/survey.ts`) состоит из трёх нажатий: куда (раздел и подраздел), что это, насколько важно. Кроме подсказок алгоритма, в нём всегда есть собственные разделы пользователя (`core/sections.ts`): их можно создать прямо в опросе кнопками «+ раздел» и «+ подраздел».
   Если ждать не хочется, опрос можно пройти сразу: кнопка «Разложить сейчас» в окне ввода (`Ctrl/⌘ + Shift + Enter`) или команда «Sort all inbox captures now» для всех входящих.
6. **Раскладка и обучение.** Плагин переносит заметку в выбранную папку как обычную заметку с frontmatter (`kind`, `importance`, `tags`). Заметка получает ссылки на похожие заметки (`suggestRelatedNotes`, общие теги и слова) и на заметку-оглавление своей папки, поэтому сразу встраивается в граф. Выбор пользователя сохраняется в `feedback`, и похожие заметки в следующий раз ранжируются точнее.
7. **Пересмотр спустя время** (`nextReviewDays` в `core/schedule.ts`). Через 7 дней после раскладки (настройка «Review after») заметка возвращается с тем же коротким опросом: текущая папка и прежние ответы уже выбраны, так что «всё верно» — одно нажатие. Важные заметки (3) возвращаются снова с удваивающимся интервалом, как в интервальном повторении. Любую заметку, включая созданные до плагина, можно разложить вручную: команда «Sort current note» или пункт «ArchiVarious: разложить» в контекстном меню файла.

## Ключевые решения по модулям и их обоснование

### 1. Монорепозиторий: pnpm workspaces

**Решение.** Один репозиторий: `packages/core`, `packages/ui`, `apps/obsidian-plugin`, `apps/widget`, управление через pnpm workspaces.

**Почему это лучший выбор.**
- У обоих продуктов общий алгоритм и общий формат данных. Если ядро изменится в одном коммите вместе с плагином и приложением, их форматы не разойдутся. С отдельными репозиториями пришлось бы публиковать пакет и синхронизировать версии.
- pnpm строго изолирует зависимости: пакет не может случайно импортировать то, что не объявил. Он быстрый и экономит диск. Tauri официально поддерживает его в шаблонах.
- Внутренние пакеты экспортируют исходники `.ts` напрямую (`"exports": "./src/index.ts"`). esbuild и Vite собирают их сами, поэтому отдельный шаг сборки ядра и проблемы с устаревшим `dist` исключены.

**Почему не другие варианты.** Nx и Turborepo дают кэширование задач, но на четырёх пакетах это лишняя конфигурация, и их можно добавить позже, не меняя структуры. Yarn и npm workspaces изолируют зависимости слабее.

### 2. Ядро (`packages/core`): чистый TypeScript без зависимостей

**Решение.** Вся логика предметной области живёт в одном пакете без зависимостей и без API платформ: формат, планировщик, алгоритм, протокол, опрос.

**Почему это лучший выбор.**
- Плагин Obsidian обязан быть на JS/TS. Если ядро тоже на TS, один и тот же код работает в плагине (Electron и мобильный Obsidian), в веб-интерфейсе Tauri и в тестах, а переписывать алгоритм на втором языке не нужно.
- Ядро не знает про Obsidian, Tauri и DOM (в `lib` указан только `ES2022`). Поэтому оно полностью покрывается быстрыми unit-тестами, и его можно перенести куда угодно, например в будущий сервер синхронизации.
- `placement.ts` задуман как точка расширения. Сейчас там детерминированный базовый алгоритм: взвешенное пересечение тегов и терминов, нормировка по размеру папки, обучение на ответах. Позже на его место можно поставить эмбеддинги или локальную модель, не трогая плагин и приложение.

**Почему не Rust/WASM-ядро.** Оно было бы быстрее на огромных хранилищах, но усложнило бы сборку плагина, увеличило бы размер `main.js` и замедлило бы итерации. Сейчас алгоритм работает с уже готовым кэшем метаданных Obsidian, и скорости TS хватает с запасом. Если профилирование покажет узкое место, горячую часть можно вынести в WASM, не меняя API ядра.

### 3. Обмен данными: протокол «Входящих» (файлы Markdown) плюс `obsidian://` URI

**Решение.** Каждая запись становится отдельным `.md`-файлом с YAML-frontmatter в папке входящих внутри хранилища. Резервный канал для мобильных устройств — URI `obsidian://archivarious?text=…`, который обрабатывает плагин.

**Почему это лучший выбор.**
- Хранилище Obsidian — это папка с Markdown. Если писать прямо в неё, работает любая синхронизация пользователя (Obsidian Sync, iCloud, Syncthing, git), и **не нужен ни сервер, ни аккаунт, ни интернет**. Для «второго мозга» с личными данными это важно.
- Запись работает, даже когда Obsidian закрыт: плагин подхватит файлы при следующем запуске.
- Каждая запись лежит в отдельном файле, поэтому при синхронизации с двух устройств нет конфликтов (в одном общем файле-очереди они были бы).
- Формат читается человеком. Если плагин удалить, заметки останутся обычными Markdown-файлами.
- URI нужен для iOS и Android, где хранилище часто лежит в песочнице Obsidian. Виджет передаёт текст в Obsidian одним нажатием.

**Почему не другие варианты.** Свой сервер или облачная база означают затраты, приватность и аккаунты, которые нужны только ради передачи одной строки. Local REST API плагины требуют запущенного Obsidian и не работают на мобильных.

**Разделы пользователя** хранятся по тому же принципу: заметка `ArchiVarious/Разделы.md` со вложенным списком (пункт = папка-раздел, вложенный пункт = подраздел). Так список общий для плагина и виджета, синхронизируется вместе с хранилищем и правится руками как обычная заметка (команда «Edit sections»). Настройки плагина (`data.json`) для этого не подошли: виджет их только читает, а записи двух программ в один JSON спорили бы друг с другом. Путь к заметке — часть контракта между приложениями (`SECTIONS_FILE` в ядре и `SECTIONS_PATH` в Rust). Это единственный файл, который виджет перезаписывает, и путь у него зашит в Rust-команде.

### 4. Общий UI: Svelte 5

**Решение.** Компонент быстрого ввода `QuickCapture` один на Svelte 5. Он встраивается и в модалку Obsidian, и в окно Tauri.

**Почему это лучший выбор.**
- Svelte компилируется в небольшой ванильный JS без тяжёлого рантайма. Для плагина это важно: весь `main.js` (вместе с ядром и UI) сейчас весит около 75 КБ. React добавил бы порядка 40+ КБ только рантайма.
- Svelte уже стал фактическим стандартом для UI в плагинах Obsidian: его используют многие популярные плагины, и есть официальная инструкция в документации Obsidian.
- Один компонент означает одинаковый ввод везде и одну точку для исправлений.

**Почему не другие варианты.** React и Vue тяжелее и проигрывают в размере бандла. Ванильный DOM годится для простых модалок (опрос в плагине сделан нативным API Obsidian), но для общего компонента на двух платформах он неудобен.

### 5. Плагин Obsidian: TypeScript + esbuild, `isDesktopOnly: false`

**Решение.** Сборка через esbuild (как в официальном `obsidian-sample-plugin`) с `esbuild-svelte`, плагин поддерживает мобильный Obsidian.

**Почему это лучший выбор.**
- Это официальный путь Obsidian. Пакеты `obsidian`, `electron` и `@codemirror/*` помечены как external, то есть берутся из Obsidian, а не дублируются в бандле.
- esbuild пересобирает за миллисекунды. Переменная `OBSIDIAN_VAULT` автоматически копирует сборку в тестовое хранилище, так что цикл разработки сводится к «сохранил и перезагрузил плагин».
- Плагин не использует Node и Electron API, поэтому работает и на мобильных: виджет-приложению на телефоне есть с кем общаться.
- Индекс хранилища строится из `metadataCache`, который Obsidian уже держит в памяти, без чтения файлов. Опрос открывается не чаще одного раза за раз и не мешает работе.

### 6. Виджет-приложение: Tauri 2

**Решение.** Одно приложение на Tauri 2: веб-интерфейс (Vite + Svelte, тот же `@archivarious/ui` и `@archivarious/core`) плюс тонкий слой на Rust. Цели: Windows, macOS, Linux, Android и iOS.

**Почему это лучший выбор.**
- **Переиспользование кода.** Ядро и UI на TS работают в приложении без изменений. Flutter (Dart) или нативные приложения потребовали бы переписать алгоритм и протокол на другом языке и потом поддерживать две копии.
- **Одна кодовая база на 5 платформ.** Начиная со второй версии Tauri официально поддерживает Android и iOS, а не только десктоп.
- **Лёгкость.** Tauri использует системный WebView, поэтому установщик весит единицы МБ, а Electron тащит с собой целый Chromium (более 100 МБ). Приложение висит в трее постоянно, так что память и время запуска имеют значение.
- **Нужные десктопные возможности есть из коробки:** официальные плагины глобальной горячей клавиши, трея, открытия URL, а также окно поверх всех без рамки в панели задач. Этого достаточно, чтобы окно работало как виджет.
- **Безопасность.** По модели capabilities у JS по умолчанию нет доступа к файловой системе. Единственная операция записи — команда `write_capture` на Rust, которая проверяет путь (никакого `..`, только `.md`, без перезаписи) и покрыта тестами.

**Почему не другие варианты.**
- *Electron:* тяжёлый и без мобильных платформ.
- *Flutter:* отличные мобильные и десктопные виджеты, но другой язык (Dart), поэтому ядро пришлось бы дублировать. Кроме того, виджеты рабочего стола iOS и Android всё равно пишутся нативно.
- *React Native:* слабая поддержка десктопа (Windows и macOS поддерживаются отдельными проектами, Linux никак) и тот же вопрос нативных виджетов.
- *Нативно на каждой платформе:* лучший UX, но 4–5 кодовых баз для одного человека.

#### Виджет на рабочем столе Windows 11

Десктопная версия приложения устроена как постоянная строка ввода, а не как всплывающее окно.

- **Окно.** Узкая безрамочная панель с прозрачным фоном и скруглёнными углами, без значка в панели задач. Высота подстраивается под содержимое (`ResizeObserver` → `setSize`): строка, опрос или настройки. Положение запоминает `tauri-plugin-window-state` (только положение, размер задаёт содержимое).
- **«Постоянно на рабочем столе».** По умолчанию окно лежит под остальными (`alwaysOnBottom`) и видно на рабочем столе. Горячая клавиша `Ctrl+Shift+Space`, иконка в трее или повторный запуск выводят его вперёд и ставят курсор в строку. Вызванный виджет остаётся впереди, пока его не уберут: Esc или повторное `Ctrl+Shift+Space` возвращают его на место. Потеря фокуса его не убирает: на Windows перетаскивание на мгновение уводит фокус из webview в окно, и виджет проваливался под окна прямо во время перетаскивания. В настройках можно выбрать режим «Поверх всех окон». Запросы на смену слоя идут через очередь, и применяется только последнее желание.
- **Автозапуск и один экземпляр.** `tauri-plugin-autostart` включает запуск вместе с Windows, `tauri-plugin-single-instance` не даёт запустить второй виджет. Закрытие окна (Alt+F4) только прячет его в трей, выход есть в меню трея.
- **Почему не «настоящий» виджет Windows 11.** Панель виджетов Windows 11 принимает только пакеты MSIX с провайдером виджетов (Windows App SDK) и показывает карточки с адаптивной разметкой, но не поле ввода текста. Обычное окно под другими окнами даёт ровно то, что нужно: строку, в которую можно сразу писать.
- **Раскладка сразу.** `Enter` сохраняет запись во «Входящие» (плагин спросит позже), `Ctrl+Enter` или кнопка ⚡ показывает опрос прямо в виджете. Виджет читает хранилище сам: Rust-команда `scan_vault` отдаёт начала заметок (по 4 КБ, без скрытых папок и «Входящих»), а `snapshotFromSnippets` из ядра строит из них тот же индекс папок, что плагин берёт из кэша Obsidian. Поэтому подсказки папок совпадают, а Obsidian может быть закрыт. Индекс подгружается, как только пользователь начал печатать.
- **Общие настройки с плагином.** Папка входящих, задержки опроса и пересмотра, ссылка на оглавление папки и обученные предпочтения читаются из `.obsidian/plugins/archivarious/data.json` (только чтение, `parseSharedSettings`). Свои обученные предпочтения виджет хранит отдельно и складывает с плагинными (`mergeFeedback`), чтобы не писать в файл, которым владеет плагин.
- **Готовая заметка.** `serializeFiledNote` пишет те же поля frontmatter, что и плагин (`kind`, `importance`, `review_at`, `review_days`), и строку «Связано:» со ссылками на оглавление папки и похожие заметки. Поэтому заметки из виджета тоже попадают в очередь пересмотра плагина.
- **Безопасность.** У JS нет доступа к файловой системе. Все операции идут через команды `write_capture`, `write_note_unique`, `ensure_note`, `scan_vault` и `read_plugin_data`. Они принимают только относительные пути внутри хранилища без `..` и скрытых папок, пишут только `.md` и никогда не перезаписывают существующий файл. Это покрыто тестами на Rust.
- **Что не проверено.** Окно проверено под WebKit на Linux (запуск, прозрачность, высота по содержимому) и сценарии интерфейса в браузере с подставным хранилищем. Поведение слоёв окна (`alwaysOnBottom`) и автозапуск именно на Windows 11 нужно проверить вручную.

### 7. Виджеты рабочего стола на телефонах: нативные расширения поверх Tauri

Ни один кроссплатформенный фреймворк не рисует виджеты рабочего стола iOS и Android своим кодом: iOS требует WidgetKit (SwiftUI), Android — App Widgets (Jetpack Glance). Поэтому план такой:

- Виджет — это маленькое нативное расширение с одной кнопкой или полем «Записать». По нажатию он открывает приложение по deep link `archivarious://capture` прямо на экране ввода.
- Вся логика (форматирование, протокол, отправка в Obsidian) остаётся в общем TS-ядре внутри приложения, а нативный код состоит буквально из десятков строк.
- Проекты `src-tauri/gen/android` и `src-tauri/gen/apple` создаются командами `pnpm --filter @archivarious/widget tauri android init` и `… tauri ios init` на машине с Android SDK и Xcode. Расширения виджетов добавляются туда же.

### 8. Качество: Vitest, Biome, svelte-check, `cargo clippy`, GitHub Actions

- **Vitest.** Нативно понимает TS и ESM, использует тот же трансформер, что и Vite, без отдельной настройки. В отличие от Jest, не требует babel и ts-jest.
- **Biome.** Один быстрый инструмент вместо ESLint + Prettier + плагинов, одна конфигурация, проверка всего репозитория занимает десятки миллисекунд. Файлы `.svelte` проверяет `svelte-check`, потому что он понимает шаблоны.
- **TypeScript в strict-режиме** с `noUncheckedIndexedAccess`: алгоритм постоянно работает со словарями, и этот флаг ловит забытые проверки на `undefined`.
- **CI** (`.github/workflows/ci.yml`): линт, типы, тесты, сборка плагина и фронтенда, проверка того, что корневой `manifest.json` синхронизирован с плагином. Отдельная задача для Rust: `fmt`, `clippy -D warnings`, тесты.
- **Релизы.** По тегу `X.Y.Z` создаётся черновик релиза плагина с `main.js`, `manifest.json` и `styles.css` (именно этот формат требует каталог плагинов Obsidian). По тегу `widget-vX.Y.Z` собираются установщики для macOS (arm64 и x64), Windows и Linux через `tauri-action`.
- **Dependabot** раз в неделю группирует обновления npm и cargo.

## Что сознательно отложено

- **Подпись приложений** (Apple notarization, сертификат Windows) и мобильные сборки в CI: нужны аккаунты разработчика.
- **Умный алгоритм** (эмбеддинги, локальная LLM): базовый алгоритм уже стоит на своём месте и обучается на ответах. Замена делается внутри `placement.ts`.
- **Синхронизация с Google Календарём.** Настоящая синхронизация требует OAuth-клиента в Google Cloud, который заводит владелец проекта (для личного использования достаточно режима «тестирования» с одним тестовым пользователем), а на телефоне плагин не может принять OAuth-перенаправление без внешнего сервера. Без этого шага её не сделать.
- **Хранилище настроек виджета.** Пока это `localStorage`. При необходимости его можно заменить на `tauri-plugin-store`.
