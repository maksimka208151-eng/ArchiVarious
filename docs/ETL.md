# PDF.js + Docling: локальное извлечение и проверяемый конспект

ETL остаётся отдельным Node.js-хостом: PDF.js и Python-зависимости не включаются
в плагин Obsidian или виджет. Оригинал сохраняется до извлечения.

## Запуск

Нужны Node.js 22.13+ и pnpm 10.28.0:

```sh
pnpm install --frozen-lockfile
pnpm etl --input ./lecture.pdf --output ./knowledge
pnpm etl --input ./lecture.pdf --output ./knowledge --extractor docling
pnpm etl --input ./lecture.pdf --output ./knowledge --extractor pdfjs
```

- `auto` (по умолчанию): сначала PDF.js; малое количество текста, повреждённые
  символы, растровые изображения или признаки колонок/таблиц вызывают Docling
  для всего документа. Эвристика консервативна, может реагировать на логотипы
  и не гарантирует обнаружение всех сложных страниц.
- `pdfjs`: только текстовый слой с отчётом о подозрительных страницах.
- `docling`: структура документа, OCR на русском/английском и таблицы.
  Ошибка Docling завершает запуск с сохранённым оригиналом.

Для учебников со сложной вёрсткой выбирайте `docling` явно.
В `auto` недоступность Docling сохраняет частичный результат PDF.js.
Лимиты: 30 МБ, 150 страниц, 120 000 символов; превышение — ошибка без обрезания.

## Установка Docling

Рекомендуется отдельное окружение Python 3.11/3.12. Windows (PowerShell):

```powershell
py -3.12 -m venv .venv-docling
.venv-docling\Scripts\python.exe -m pip install -r apps/etl/python/requirements.txt
$env:ARCHIVARIOUS_PYTHON = (Resolve-Path .venv-docling\Scripts\python.exe).Path
```

macOS/Linux:

```sh
python3 -m venv .venv-docling
.venv-docling/bin/python -m pip install -r apps/etl/python/requirements.txt
export ARCHIVARIOUS_PYTHON="$PWD/.venv-docling/bin/python"
```

Без переменной используется `python` из PATH. Значение — путь к одному исполняемому
файлу, без аргументов оболочки. Docling работает на CPU, удалённые сервисы отключены.
Первый запуск может скачать веса Docling/EasyOCR; после подготовки моделей
обработка может выполняться без сети. Таймаут конвертации — 5 минут.
Первый запуск при медленном скачивании может потребовать повторения после подготовки моделей.

Отдельное распознавание формул пока отключено. Обнаруженные формулы и изображения
требуют проверки; изображения не описываются моделью. Сложные формулы могут также
попасть в обычный текст и не получить отдельной отметки. Нельзя считать OCR точной
транскрипцией без сравнения с оригиналом.

## Конспект

Установите `AI_GATEWAY_API_KEY` и выберите действительную модель:

```sh
pnpm etl --input ./lecture.pdf --output ./knowledge --model provider/model
```

Только выбор модели отправляет извлечённый текст, предупреждения и отчёт по страницам
через AI Gateway; возможны расходы по тарифу провайдера.
При статусе `partial` вызов LLM блокируется. Сначала проверьте пропуски в `source.json`.
Явный `--allow-partial` разрешает конспект по доступному содержимому, сохраняя статус
`partial` и заметное предупреждение в Markdown.

Каждый тезис обязан иметь дословную цитату из существующего фрагмента.
Проверка подтверждает происхождение цитаты, но не её соответствие тезису,
точность OCR или полноту конспекта. Числа, формулы и таблицы сверяйте с оригиналом.
Синтез по разделам ещё не реализован: конспект создаётся одним запросом.

## Результат

В `knowledge/<run-id>/`:

- `original.pdf` — исходные байты, сохраняются до извлечения;
- `source.json` — SHA-256, фрагменты, предупреждения, обработчик, версия Docling,
  статус и отчёт по каждой странице;
- `extracted.md` — текст и ID фрагментов;
- `run.json` — параметры и начальный статус;
- `summary.json`, `summary.md`, `completed.json` — результат успешной генерации,
  итоговый статус может быть `complete` или `partial`;
- `failed.json` — ошибка извлечения/синтеза; доступные исходные данные сохраняются.

Без модели конечный статус находится в `run.json`: `extracted` или `partial`.
`complete` означает отсутствие обнаруженных пропусков, а не гарантию правильного
понимания всех элементов PDF. Пустые страницы также могут требовать проверки.
Docling сохраняет тип блока и координаты в PDF-точках с явным началом координат.
Блоки, пересекающие несколько страниц, пропускаются с отметками этих страниц.
Подсветки области в интерфейсе пока нет. Контракт `schemaVersion: 1` расширен
необязательными полями; старые экспорты остаются совместимы.

Для Obsidian направьте `--output` в хранилище либо перенесите папку запуска целиком.
Кнопки импорта в плагине пока нет.

## Проверки

`pnpm check`: линт, типизация, существующие тесты и `test:hybrid`.
Новые проверки используют реальные цифровые PDF и подставной ответ Docling:
маршрутизация, пропуски, геометрия, таблицы, ссылки, лимиты и блокировка LLM.
Workflow `PDF integration` устанавливает настоящий Docling и проверяет смешанный
цифровой/сканированный PDF. Это проверка интеграции, не оценка качества на учебниках.

Перед постоянным использованием нужно сравнить 5–10 реальных PDF: русский текст,
ЗФТШ с формулами, таблицы, сканы, многоколоночные статьи. Проверять пропуски,
порядок чтения, числа/формулы, время и память.
