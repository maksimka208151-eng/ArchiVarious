# Первый этап ETL: PDF с проверяемыми цитатами

ArchiVarious развивается в контейнер знаний: исходные материалы → извлечение →
единое представление → синтез с доказательствами → экспорт. Плагин и виджет
остаются точками быстрого ввода. `apps/etl` — отдельный локальный Node-хост,
который не добавляет PDF-парсер и облачные зависимости в мобильный плагин.

## Что работает

- Чтение PDF с текстовым слоем, извлечение по страницам через PDF.js.
- Сохранение оригинальных байтов, SHA-256, номера страницы и ID каждого фрагмента.
- Локальное извлечение без отправки данных в сеть.
- По явному выбору модели — структурированный конспект через AI SDK / AI Gateway.
- Проверка каждого fragmentId и дословного вхождения цитаты в соответствующий фрагмент.
- Экспорт Markdown с относительными ссылками на PDF и извлечённый текст.
- Отдельная папка на каждый запуск: повторный запуск не затирает прошлые данные.

## Запуск

Нужны Node.js 22.13+ и pnpm 10.28.0. Из корня репозитория:

```sh
pnpm install --frozen-lockfile
pnpm etl --input ./lecture.pdf --output ./knowledge
```

Первая команда ETL только извлекает текст. Чтобы создать конспект, установите
`AI_GATEWAY_API_KEY` в окружении и явно выберите доступную модель с поддержкой
структурированного вывода:

```sh
pnpm etl --input ./lecture.pdf --output ./knowledge --model provider/model
```

`provider/model` — шаблон, замените его действительным идентификатором из каталога
вашего AI Gateway. При указании `--model` извлечённый текст отправляется
провайдеру через шлюз; возможны расходы по вашему тарифу. Секрет не передавайте
аргументом команды и не сохраняйте в репозиторий. Для переноса результата в
Obsidian скопируйте всю папку запуска: относительные ссылки сохранятся.

## Результат

В `knowledge/<hash>-<run-id>/`:

- `original.pdf` — исходный файл;
- `source.json` — версия контракта, SHA-256, текстовые фрагменты и предупреждения;
- `extracted.md` — читаемый текст с заголовками `p1-f1`, `p2-f1` и т. д.;
- `run.json` — начальные параметры запуска и выбранная модель;
- `summary.json`, `summary.md`, `completed.json` — только после успешного синтеза и проверки;
- `failed.json` — если генерация или проверка завершились ошибкой. Исходные данные сохраняются.

`run.json` фиксирует начальный этап; итог смотрите в `completed.json` или
`failed.json`. При локальном извлечении статус `extracted` является конечным.

## Границы первой версии

До 30 МБ, 150 страниц и 120 000 извлечённых символов. Превышение лимита — ошибка,
текст не обрезается молча. Полностью сканированный PDF отклоняется с просьбой
использовать OCR; страницы с малым количеством текста отмечаются предупреждениями.
Изображения, диаграммы и структура таблиц не интерпретируются. Порядок чтения
сложных многоколоночных документов требует ручной проверки.

Проверка цитат подтверждает происхождение, **но не логическое соответствие тезиса
цитате и не полноту конспекта**. Выход обозначен как черновик ИИ. Никакой
автоматической оценки достоверности или гарантии качества обучения здесь нет.
Сбой модели не вызывает повторные платные запросы автоматически.

Сейчас это CLI; кнопки загрузки в виджете и плагине ещё нет. Аудио, видео,
презентации, таблицы и многодокументный синтез — следующие адаптеры, пока не реализованы.

## Проверки

`pnpm check`: линт, типы всех пакетов, тесты существующей логики и ETL.
Тесты используют реальный небольшой PDF и подставной генератор для сквозной
проверки; они не вызывают платные API. Успешный реальный вызов модели требует
отдельной проверки с ключом и выбранной моделью.
