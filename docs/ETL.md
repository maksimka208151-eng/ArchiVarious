# PDF.js + Docling: локальное извлечение и проверяемый конспект

ETL остаётся отдельным Node.js-хостом: PDF.js и Python-зависимости не включаются
в плагин Obsidian или виджет. Оригинал сохраняется до извлечения.

## Запуск

Нужны Node.js 22.13+ и pnpm 10.28.0:

```sh
pnpm install --frozen-lockfile
pnpm etl --input ./lecture.pdf --output ./knowledge
pnpm etl --input ./lecture.pdf --output ./knowledge --extractor docling
pnpm etl --input ./lecture.pdf --output ./knowledge --extractor pdfjs
```

- `auto` (по умолчанию): сначала PDF.js; малое количество текста, повреждённые
  символы, растровые изображения или признаки колонок/таблиц вызывают Docling
  для всего документа. Эвристика консервативна, может реагировать на логотипы
  и не гарантирует обнаружение всех сложных страниц.
- `pdfjs`: только текстовый слой с отчётом о подозрительных страницах.
- `docling`: структура документа, OCR на русском/английском и таблицы.
  Ошибка Docling завершает запуск с сохранённым оригиналом.

Для учебников со сложной вёрсткой выбирайте `docling` явно.
В `auto` недоступность Docling сохраняет частичный результат PDF.js.
Если нет ни одного читаемого фрагмента, запуск завершается с ошибкой, даже без модели
и с `--allow-partial`. Оригинал, source.json и непустой extracted.md с объяснением
сохраняются. В failed.json указан этап extraction; это не успешное извлечение.
Причина недоступности Python/пакета или превышение таймаута показывается без
включения необработанного stderr в журнал. Для диагностики используйте
`--extractor docling`: ошибка не будет заменена результатом PDF.js.
Лимиты: 30 МБ, 150 страниц, 120 000 символов; превышение — ошибка без обрезания.

## Установка Docling

Рекомендуется отдельное окружение Python 3.11/3.12. Windows (PowerShell):

```powershell
py -3.12 -m venv .venv-docling
.venv-docling\Scripts\python.exe -m pip install -r apps/etl/python/requirements.txt
$env:ARCHIVARIOUS_PYTHON = (Resolve-Path .venv-docling\Scripts\python.exe).Path
```

macOS/Linux:

```sh
python3 -m venv .venv-docling
.venv-docling/bin/python -m pip install -r apps/etl/python/requirements.txt
export ARCHIVARIOUS_PYTHON="$PWD/.venv-docling/bin/python"
```

Без переменной используется `python` из PATH. Значение — путь к одному исполняемому
файлу, без аргументов оболочки. Docling работает на CPU, удалённые сервисы отключены.
Первый запуск может скачать веса Docling/EasyOCR; после подготовки моделей
обработка может выполняться без сети. По умолчанию таймаут конвертации — 5 минут; `--ocr-timeout 900` задаёт 15 минут.
Первый запуск при медленном скачивании может потребовать повторения после подготовки моделей.

Отдельное распознавание формул пока отключено. Обнаруженные формулы и изображения
требуют проверки; изображения не описываются моделью. Сложные формулы могут также
попасть в обычный текст и не получить отдельной отметки. Нельзя считать OCR точной
транскрипцией без сравнения с оригиналом.

## Конспект

Установите `AI_GATEWAY_API_KEY` и выберите действительную модель:

```sh
pnpm etl --input ./lecture.pdf --output ./knowledge --model provider/model
```

В режиме `--provider gateway` (по умолчанию) выбор `--model` отправляет извлечённый текст, предупреждения и отчёт по страницам
через AI Gateway; возможны расходы по тарифу провайдера.
При статусе `partial` вызов LLM блокируется. Сначала проверьте пропуски в `source.json`.
Явный `--allow-partial` разрешает конспект по доступному содержимому, сохраняя статус
`partial` и заметное предупреждение в Markdown.

Каждый тезис обязан иметь дословную цитату из существующего фрагмента.
Проверка подтверждает происхождение цитаты, но не её соответствие тезису,
точность OCR или полноту конспекта. Числа, формулы и таблицы сверяйте с оригиналом.
AI Gateway пока создаёт конспект одним запросом. Локальный режим ниже обрабатывает текст частями.

## Результат

В `knowledge/<run-id>/`:

- `original.pdf` — исходные байты, сохраняются до извлечения;
- `source.json` — SHA-256, фрагменты, предупреждения, обработчик, версия Docling,
  статус и отчёт по каждой странице;
- `extracted.md` — текст и ID фрагментов;
- `run.json` — параметры и начальный статус;
- `summary.json`, `summary.md`, `completed.json` — результат успешной генерации,
  итоговый статус может быть `complete` или `partial`;
- `failed.json` — ошибка извлечения/синтеза; доступные исходные данные сохраняются.

Без модели конечный статус находится в `run.json`: `extracted` или `partial`.
`complete` означает отсутствие обнаруженных пропусков, а не гарантию правильного
понимания всех элементов PDF. Пустые страницы также могут требовать проверки.
Docling сохраняет тип блока и координаты в PDF-точках с явным началом координат.
Блоки, пересекающие несколько страниц, пропускаются с отметками этих страниц.
Подсветки области в интерфейсе пока нет. Контракт `schemaVersion: 1` расширен
необязательными полями; старые экспорты остаются совместимы.

Для Obsidian направьте `--output` в хранилище либо перенесите папку запуска целиком.
Кнопки импорта в плагине пока нет.

## Проверки

`pnpm check`: линт, типизация, существующие тесты и `test:hybrid`.
Новые проверки используют реальные цифровые PDF и подставной ответ Docling:
маршрутизация, пропуски, геометрия, таблицы, ссылки, лимиты и блокировка LLM.
Workflow `PDF integration` устанавливает настоящий Docling и проверяет смешанный
цифровой/сканированный PDF. Это проверка интеграции, не оценка качества на учебниках.

Перед постоянным использованием нужно сравнить несколько реальных PDF: русский текст,
ЗФТШ с формулами, таблицы, сканы, многоколоночные статьи. Проверять пропуски,
порядок чтения, числа/формулы, время и память.

## Подбор OCR на реальных сканах

Внутри Docling можно выбрать движок:

```sh
pnpm etl --input ./slides.pdf --output ./knowledge --extractor docling --ocr-engine tesseract --ocr-timeout 900
```

`tesseract` требует отдельно установленного Tesseract 5 в PATH и языков `rus`, `eng`.
Проверка: `tesseract --list-langs`. Если задаёте TESSDATA_PREFIX, в указанной папке
должны быть не только traineddata, но и штатные configs Tesseract (включая tsv).
`easyocr` остаётся вариантом по умолчанию и устанавливается с Python-зависимостями.
Полностью сканированные документы передаются с принудительным OCR всей страницы.
Выбранный движок и таймаут записываются в run.json; движок OCR также входит в source.json.

На выборке страниц презентации «Аддитивные технологии» Tesseract сохранил
больше русского текста, чем EasyOCR, но оба ошибались в смешанных русских/латинских
обозначениях. Это наблюдение для одного документа, а не универсальный рейтинг.
Не заменяйте распознанные цитаты правками LLM без отдельной отметки: CAD, ABS,
G-код, числа и формулы нужно проверять по оригиналу.

`--ocr-scale` задаёт масштаб рендера 1–4 (по умолчанию 3, то есть 216 DPI).
Больше не всегда лучше: на проверенной презентации масштаб 2 восстановил FDM/Z
лучше, чем 3, но изменил порядок блоков на странице с карточками. Выбор масштаба
не считается автоматической гарантией качества. Сравнивайте несколько страниц,
включая таблицы и подписи; настройка фиксируется в run.json.

## Локальный Qwen3.5-9B: первый прототип

Главный кандидат — Qwen3.5-9B в GGUF Q4_K_M. Нужен актуальный llama.cpp с поддержкой
Qwen3.5, CUDA-сборка для NVIDIA и скачанный GGUF. Установка llama.cpp:
https://github.com/ggml-org/llama.cpp/releases . Исходная модель:
https://huggingface.co/Qwen/Qwen3.5-9B . Один из доступных источников GGUF:
https://huggingface.co/unsloth/Qwen3.5-9B-GGUF/tree/main (выберите Q4_K_M).
Квантованные веса сторонних авторов
отличаются от исходных; фиксируйте автора, имя файла и версию llama.cpp при сравнении.

Первый запуск в PowerShell, из корня репозитория (замените путь к весам):

```powershell
llama-server -m .\models\Qwen3.5-9B-Q4_K_M.gguf --alias qwen3.5-9b --ctx-size 8192 --parallel 1 --gpu-layers 99 --host 127.0.0.1 --port 8080 --jinja --no-mmproj --no-context-shift --cache-type-k q8_0 --cache-type-v q8_0
```

Это стартовая конфигурация для измерения, не проверенный профиль RTX 3060 Ti 8 ГБ.
Если не хватает VRAM, уменьшайте `--gpu-layers` (например, до 24): часть весов
перейдёт на CPU/RAM, скорость нужно измерить. При 16 ГБ RAM закройте тяжёлые приложения.
Начните с 8192 токенов, затем отдельно измеряйте 16384. Заявленный моделью контекст
не означает, что он помещается на этой видеокарте. В этом режиме vision-проектор
не загружается; OCR работает на CPU и заканчивается до вызова модели.

В другом окне PowerShell, также из корня репозитория:

```powershell
pnpm etl --input ./lecture.pdf --output ./knowledge --provider local --extractor docling --ocr-engine tesseract --ocr-timeout 900
```

Для проверенной презентации с изображениями статус остаётся partial. После просмотра
предупреждений разрешить черновик по доступному тексту можно добавлением `--allow-partial`.
Ключ AI Gateway не нужен. Текст направляется только на указанный loopback-сервер;
перенаправления запрещены. Сервер сам должен быть настроен для локальной обработки.
`--model` в локальном режиме задаёт alias сервера; по умолчанию `qwen3.5-9b`.
При работе через LM Studio укажите, например, `--endpoint http://127.0.0.1:1234/v1`
и `--model` с загруженным идентификатором. Совместимость именно с LM Studio здесь не проверялась.

Локальный адаптер отправляет последовательные части до 6000 символов, по возможности
сохраняя границы строк/слов. Это ограничение текста, а не измерение токенов всей заявки:
добавляются инструкции, JSON и предупреждения. `--batch-chars 3000` уменьшает части,
`--llm-timeout 900` увеличивает таймаут одной части. Ответ ограничен 4096 токенами.
Модель выбирает идентификаторы отрывков из текущей части, а ETL подставляет
точный текст цитат. Обрезанный ответ, неверный JSON или неизвестный идентификатор
останавливают запуск. Лимит 30 тезисов применяется к каждой части.
Если сервер сообщает нехватку контекста, уменьшайте часть; автоматического обрезания нет.

Тезисы частей объединяются в исходном порядке вместе с доказательствами. Повторного
сжатия общим запросом пока нет: возможны повторы, а связи через границу частей могут
потеряться. Это первый вариант для оценки качества, не готовый конспектировщик учебников.

Дополнительные результаты:

- `batch-NNN.json` — каждый успешно проверенный ответ; остаётся при сбое следующей части;
- `rejected-batch-NNN.json` — отклонённый ответ модели и исходные отрывки для диагностики;
- `coverage.json` — ID отправленных фрагментов, ID процитированных и фрагментов без цитат;
- `run.json.generation` — провайдер, адрес, размер части и таймаут;
- `summary.md` — черновик со ссылками на страницы и цитатами.

Coverage — механический учёт. Цитирование одного предложения не означает сохранение
всех фактов фрагмента; точная цитата не доказывает, что тезис следует из неё.
Проверки адаптера используют локальный HTTP-сервер с подставными ответами: это проверка
протокола и блокировок, не качества Qwen. Реальный прогон модели на RTX 3060 Ti ещё нужен.
Vision-чтение страниц в этот прототип не входит.

Для оценки возьмите 5–8 страниц с определениями, таблицей, числами и схемой.
До генерации выпишите обязательные факты по оригиналу. Сравнивайте пропуски, искажения,
неподтверждённые добавления, правильность страниц/цитат, время и пиковую память.
Успешный запуск или связный русский текст сами по себе не доказывают качество.

## Импорт документов из Obsidian

В настольном Obsidian откройте команду «Импортировать документы (PDF, TXT, Markdown)»
через палитру команд. Перетащите файлы в окно импорта или выберите их с диска.
TXT и Markdown читаются в UTF-8. Для PDF подключается Docling при необходимости OCR.
Ссылки и вложения Markdown, визуальный смысл иллюстраций PDF и форматы DOCX/PPTX
не входят в этот режим.

В корне репозитория выполните:

```powershell
npx --yes pnpm@10.28.0 install --frozen-lockfile
npx --yes pnpm@10.28.0 build:plugin
```

Перенесите `main.js`, `manifest.json` и `styles.css` из `apps/obsidian-plugin`
в `.obsidian/plugins/archivarious` вашего хранилища. Установите или перезагрузите
плагин в Obsidian. В его настройках укажите абсолютный путь к корню репозитория.
Для OCR можно указать путь к уже установленному Python Docling,
например `C:\Users\maksi\Documents\ArchiVarious\.venv-docling\Scripts\python.exe`.
Если Obsidian не находит Node.js, укажите путь к `node.exe` (Node.js 22+).

Импорт использует локальный сервер по адресу `http://127.0.0.1:8080/v1`.
Укажите имя модели, совпадающее с `--alias` при запуске сервера. Результаты
появляются в отдельной папке каждого запуска под `ArchiVarious/Документы`.
Там лежат исходник, `extracted.md` и, при успешной проверке, `summary.md`.
Если в PDF остались нечитаемые части, разрешите частичную обработку в окне импорта,
чтобы получить конспект доступного текста с отметкой о пропусках.
Если конспект отклонён, извлечённый текст и диагностика остаются доступными.

### Bonsai 2.5 27B на NVIDIA с 8 ГБ VRAM

Возьмите [PTQ1_0 без MTP](https://huggingface.co/prism-ml/Ternary-Bonsai-2.5-27B-GGUF/blob/main/Ternary-Bonsai-2.5-27B-PTQ1_0.gguf)
и [Windows x64 CUDA-сборку PrismML](https://github.com/PrismML-Eng/llama.cpp/releases/latest).
Распакуйте DLL соответствующей версии CUDA рядом с программой, если они нужны.
Формат PTQ1_0 требует сборки PrismML. Стартовый профиль для проверки на 3060 Ti:

```powershell
.\llama-server.exe -m ".\Ternary-Bonsai-2.5-27B-PTQ1_0.gguf" --alias bonsai-2.5-27b --host 127.0.0.1 --port 8080 -c 8192 -np 1 -ngl 99 -fa on --jinja --no-mmproj --min-p 0
```

Остановите старый сервер, если он занимает порт 8080. Проверка загрузки модели:

```powershell
(Invoke-RestMethod http://127.0.0.1:8080/v1/models).data | Select-Object id
```

Ожидаемый ID — `bonsai-2.5-27b`. При нехватке памяти попробуйте уменьшить
GPU-offload, например до `-ngl 48`, и измерьте скорость. 5,93 ГБ — размер
весов, а память процесса также нужна для контекста и вычислений.
Сравните Bonsai и Qwen на одном документе по точности тезисов, охвату и времени.
